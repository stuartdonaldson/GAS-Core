# Best Practice: Test Reporting for GAS Projects with Allure

## Overview

GAS projects running pytest (Python acceptance tests) and Playwright (browser tests) produce JUnit XML and Allure result files. This pattern consolidates those into a single Allure report stamped with the deployment version, with history trends accumulating across runs and per-run isolation so each report shows exactly what was tested against which deployment.

**Provenance:** Extracted from [GActionSheet](../../../../c-dev/GActionSheet). Reference files in that project:
- `write-environment.py` — cleans results dir, copies history, writes deployment stamp
- `test-results/allure-results/categories.json` — failure category definitions
- `tests/playwright/playwright.config.js` — reporter config, `outputDir`, `testIgnore`
- `pyproject.toml` — `addopts` with `--alluredir`
- `package.json` — `test:prep`, `test:smoke`, `test:full`, `test:report`, `test:serve`, `test:cycle`

---

## Problem

Running pytest and Playwright across multiple deploys produces test results that need to answer: *what ran, against what deployment, and did it pass?* Without a reporting contract:

- Results from different runs accumulate and mix — you can't tell which run a failure came from
- There is no deployment correlation — you don't know if a failure was on @181 or @182
- Failure triage has no structure — product regressions look the same as environment noise

Allure Report solves the reporting side. The pattern here solves the integration: clean per-run isolation, deployment stamping, and history continuity.

## Directory Contract

```
test-results/
  allure-results/          ← both pytest and playwright write here; cleaned before each run
    categories.json        ← tracked in git; failure category definitions
    environment.properties ← generated by write-environment.py before each run
    history/               ← copied from allure-report/history/ before each run (trend continuity)
    *.json                 ← per-test result files (gitignored)
  junit/                   ← JUnit XML (lightweight consumers, archive)
    pytest.xml
    playwright.xml
  playwright/              ← playwright artifacts: screenshots, videos (gitignored)
deployment-ledger/
  test.jsonl               ← one JSON line per deployment; written by manage-deployments
allure-report/             ← generated HTML report (gitignored)
```

**.gitignore additions:**
```
test-results/allure-results/*.json
test-results/allure-results/environment.properties
test-results/junit/
test-results/playwright/
allure-report/
```
`categories.json` is tracked; add `!test-results/allure-results/categories.json` after the `*.json` exclusion.

## Architecture

```
deploy:test  ──► deployment-ledger/test.jsonl  (appends one entry)
                        │
test:prep  ─────────────┤
  write-environment.py  │
    ├─ clean allure-results/        (removes stale results)
    ├─ copy allure-report/history/  (preserves trend data)
    └─ write environment.properties (stamps deployment version)
                        │
pytest ─────────────────┤──► allure-results/*.json
                        │    junit/pytest.xml
playwright ─────────────┤──► allure-results/*.json
                        │    junit/playwright.xml
                        │    playwright/ (screenshots, videos on failure)
test:report ────────────┤
  allure generate ──────┴──► allure-report/  (HTML, history/)
                              │
test:serve ──────────────────► browser: http://localhost:5050
```

## How It Works

### 1. Per-run isolation via write-environment.py

`write-environment.py` runs before every test suite. It:

1. **Cleans** `allure-results/` — deletes all result JSON, attachment, and properties files. Preserves `categories.json`.
2. **Copies history** from `allure-report/history/` into `allure-results/history/` so Allure can build trend graphs.
3. **Writes `environment.properties`** from the latest deployment-ledger entry:
   ```properties
   deployment.version=@182
   deployment.timestamp=2026-06-05T12:08:11Z
   deployment.target=test
   deployment.description=TEST-WEB-APP v0.2.1 (Rev. Jun 5, 2026 05:08) (TEST)
   ```

This means every report is stamped with the deployment it tested, and each report shows exactly one run's results — not a mix of all historical runs.

### 2. History continuity

Allure trends work by reading a `history/` directory inside `allure-results/` before generating the report. The `write-environment.py` copy step handles this automatically. On first run, `allure-report/history/` doesn't exist — the prep script logs `INFO: no prior history` and continues cleanly.

### 3. Failure categories

`categories.json` classifies failures into named buckets visible in the Allure "Categories" view:

```json
[
  { "name": "ATDD Pending",        "matchedStatuses": ["skipped"],          "messageRegex": ".*pending:.*" },
  { "name": "Product Regression",  "matchedStatuses": ["failed"],           "messageRegex": ".*AssertionError.*|.*toBeVisible.*|.*toHaveText.*" },
  { "name": "Perf / Timeout",      "matchedStatuses": ["failed", "broken"], "messageRegex": ".*[Tt]imeout.*" },
  { "name": "Environment / Config","matchedStatuses": ["broken"],           "messageRegex": ".*ConnectionError.*|.*HTTPError.*|.*401.*|.*403.*|.*429.*" }
]
```

ATDD pending tests (pytest `@pytest.mark.xfail(reason="pending: ...")`) appear as expected failures and are not flagged as product regressions.

### 4. Playwright outputDir isolation

Playwright's default `outputDir` is `test-results/` — it **cleans this directory at the start of every run**, which would wipe `allure-results/` and `junit/`. Set an explicit `outputDir` to avoid this:

```javascript
// playwright.config.js
outputDir: path.join(__dirname, '..', '..', 'test-results', 'playwright'),
```

Also use absolute paths for reporter outputs so they resolve correctly regardless of where `npx playwright test` is invoked:

```javascript
reporter: [
  ['list'],
  ['allure-playwright', { resultsDir: path.join(__dirname, '..', '..', 'test-results', 'allure-results') }],
  ['junit', { outputFile: path.join(__dirname, '..', '..', 'test-results', 'junit', 'playwright.xml') }],
],
```

### 5. Probe / environment tests

Tests that verify the deployment environment (auth, HTTP access, surface availability) rather than product behaviour should be excluded from standard test cycles. Use `testIgnore` in `playwright.config.js` and keep them on a dedicated npm script:

```javascript
testIgnore: ['**/probe.test.js'],
```

```json
"probe": "... npx playwright test tests/playwright/probe.test.js ..."
```

## npm Scripts

```json
"test:prep":   "/path/to/venv/python3 write-environment.py",
"test:smoke":  "npm run test:prep && npx playwright test tests/playwright/smoke.test.js --config tests/playwright/playwright.config.js",
"test:full":   "npm run test:prep && python3 -m pytest --alluredir=test-results/allure-results --junitxml=test-results/junit/pytest.xml && npx playwright test --config tests/playwright/playwright.config.js",
"test:report": "npx allure generate test-results/allure-results -o allure-report --clean",
"test:serve":  "npm run test:report && npx allure open allure-report -h 0.0.0.0 -p 5050",
"test:cycle":  "npm run test:full; npm run test:report"
```

`test:cycle` uses `;` not `&&` — the report generates even when tests fail (that is when you need it most).

`test:serve` always regenerates before opening so it reflects the latest run regardless of which test scripts ran since the last `test:cycle`.

On WSL2, `allure open` cannot launch a Windows browser. Use `-h 0.0.0.0 -p 5050` and open `http://localhost:5050` manually in the Windows browser.

## pyproject.toml

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "--alluredir=test-results/allure-results --junitxml=test-results/junit/pytest.xml"
```

## Smoke Test Pattern

A smoke test confirms the basic user surface works after any deploy — browser opens, add-on is installed, version is visible. Keep it fast (< 30s) and separate from the full suite:

```javascript
// smoke.test.js
test('@smoke sidebar opens on test doc and deployed version is visible', async ({ page }) => {
  const settings = loadSettings();
  await openDocSidebar(page, settings.testDocId);
  const sidebar = await findAddonFrame(page, 30000);
  await expect(sidebar.getByText(/^v\d+\.\d+\.\d+/)).toBeVisible({ timeout: 10000 });
});
```

Tag tests with `@smoke` in their title to allow `--grep @smoke` filtering when building composite smoke plans later.

## Viewing Historical Runs

Allure Report shows the **current run** plus history trend graphs. It does not provide a UI to browse a past run's full results (that requires Allure TestOps, the paid product).

To replay a specific past run, archive the results directory after generating:

```bash
cp -r test-results/allure-results test-results/runs/$(date -u +%Y%m%d-%H%M%S)
```

Then to view that run later:

```bash
npx allure generate test-results/runs/20260605-120000 -o allure-report --clean
npm run test:serve
```

## Common Issues

| Symptom | Cause | Fix |
|---|---|---|
| Report shows results from previous runs mixed in | `allure-results/` not cleaned before run | Ensure `test:prep` runs `write-environment.py` before tests |
| Report is empty after test run | Playwright's default `outputDir` wiped `allure-results/` | Set explicit `outputDir` in `playwright.config.js` |
| Playwright allure results missing | `resultsDir` relative path resolved against CWD not config file | Use `path.join(__dirname, ...)` for all reporter output paths |
| `allure generate` fails — Java not found | `allure-commandline` requires Java | `sudo apt-get update && sudo apt-get install -y default-jre-headless` |
| History trend shows no data | `allure-report/history/` absent on first run | Expected — trend data starts accumulating from the second run onward |
| `allure serve` can't open browser (WSL2) | No native browser in WSL2 Linux environment | Use `allure open` with `-h 0.0.0.0 -p 5050`, open `http://localhost:5050` in Windows browser |
